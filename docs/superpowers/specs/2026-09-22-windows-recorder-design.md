# JDAD Recorder Windows 版设计

状态：待用户评审，尚未开始 Windows 产品代码实现。
基线：Mac 0.4.2；目标为同一团队提供相近的录制与剪辑体验。

## 交付范围

首版目标为 Windows 11、Intel/AMD x64 桌面电脑，中文界面。Windows ARM 和 Windows 10 不作为本轮承诺范围。沿用 JDAD Recorder 名称及视觉风格，已有 Mac 工程保持不变。分享通过本地文件完成。

必须覆盖：
- 显示器、应用窗口、单屏矩形区域录制；倒计时、明确停止按钮和托盘停止入口。
- 麦克风可选，默认关闭；不开启麦克风也能完成录制、剪辑和导出。
- 实际鼠标点击触发平滑自动聚焦；支持手动添加/删除、倍率、可视化位置调整、拖动聚焦条两端改时长。
- 播放、选区裁剪/删除、Ctrl+B 分割、拖动片段排序、自动紧密拼接、边界吸附、时间轴缩放、撤销/重做。
- MP4（H.264，有录音时 AAC）和 GIF 导出；整片或选区、进度、取消、保存位置。
- 原素材保留、自动保存、本地工程重开、导入 MP4/MOV。
- 左下角按钮“发现更多应用与功能”，交给默认浏览器打开 https://jdauto.joyapp.jd.com/ 。

不扩展云分享、账号、系统音频、字幕、摄像头和多轨编辑。首版不承诺 Mac 与 Windows 工程直接双向互开；可通过 MP4 交换素材。

## 实现路线与选择

推荐 Electron + TypeScript 编辑器，配合 Windows 原生鼠标采集组件和 FFmpeg 媒体处理。理由是桌面编辑器交互容易验证，预览、时间轴和剪辑算法可以集中实现，并有成熟的 Windows 安装包工具。代价是安装体积及空闲内存通常高于原生 Mac 版。

备选为 C# 原生 Windows 桌面应用。它与操作系统集成更直接，但界面和媒体链路都需从头实现，且当前 Mac 环境无法进行 Windows 窗口交互验收。浏览器网页方案不采用，因为网页内事件无法替代其他应用中的全局鼠标点击记录。

Mac 的 ScreenCaptureKit、AVFoundation 和 SwiftUI 不直接复用。复用产品规则、行为测试场景及数学逻辑，不能声称原有 Swift 媒体模块已在 Windows 运行。

## 模块和数据流

1. Electron 主进程负责来源枚举、受控文件访问、工程管理、导出任务与托盘。
2. 渲染进程负责中文界面、视频预览、可视化聚焦与时间轴。开启上下文隔离，不暴露任意文件路径执行或 shell 调用能力。
3. 捕获通过 desktopCapturer / display-media 请求处理器绑定用户选中的来源。区域选择坐标属于指定屏幕；录制数据经分块落盘，避免把长视频全部放入内存。
4. Windows 鼠标组件使用系统事件接口记录位置和点击，不监听键盘内容。只在录制期间运行；回调轻量排队，停止/失败/退出时移除监听。
5. 单调时间轴对齐录制与鼠标事件；保存归一化位置。屏幕物理像素、界面逻辑像素和缩放比例显式转换，覆盖副屏负原点和混合 DPI。窗口移动/改尺寸时更新源边界；无法可靠映射时不生成错误聚焦。
6. 编辑决策保存为有序源区间。分割/删除/重排不覆盖源素材。镜头评价器根据映射后的源时间生成裁切矩形，预览与导出共享镜头轨迹与量化规则。
7. FFmpeg 负责媒体标准化、音频拼接、编码及 GIF 调色板。导出通过受限队列、流或磁盘中间产物控制内存；使用参数数组而非拼接 shell 命令。实际构建需明确 FFmpeg 分发来源、校验及许可材料，不直接挪用 Mac 二进制。

工程包含版本化 JSON、相对素材路径、鼠标事件和可重建缓存。原子保存；拒绝工程目录外的素材引用和覆盖源文件的导出路径。

## 交互与失败处理

录制页提供“屏幕 / 窗口”和“指定区域”；区域框支持移动、四角调整、Enter 确认、Esc 取消。未选有效区域时禁止开始；框选遮罩和控制窗不应进入成片。

聚焦位置编辑显示完整原画、可拖动的聚焦框和放大效果。应用一次形成一条撤销记录，取消不改变工程。

状态为 idle → preparing → recording → stopping → editing → exporting。重复开始、保存未完成时退出、取消导出、麦克风拒绝、来源关闭、磁盘写入失败必须有明确状态和提示。麦克风失败应允许用户选择无声录制；不得假装已经获得录制权限。

无鼠标事件时保留原画并提示可手动聚焦；不能用合成点击冒充自动跟随。窗口最小化、受保护内容和远程桌面等可能影响捕获，必须据实反馈。

## 验证与安装包

- 核心自动化：对齐现有 Mac 的剪辑映射、边界吸附、聚焦片段、动画、撤销、路径保护及项目校验案例。
- 媒体集成：合成色块和音频脉冲，真正编码并解码 MP4/GIF，检查重排顺序、时长、聚焦区域与音画同步；验证取消时保留原目标。
- Windows 实机：不开麦/开麦、三种录制方式、鼠标点击、区域外过滤、窗口移动/关闭、多显示器、100%/150%/200% DPI、至少 10 分钟录制、导出、重开工程、安装/卸载。
- 交付源码、构建说明、测试记录以及 Windows x64 安装包（目标为 NSIS .exe）。只有实际生成并验证的包才标记为已交付；交叉打包成功不等同于 Windows 实机通过。
- Windows 签名证书未提供；未签名测试安装包可能受 SmartScreen/企业策略拦截，正式分发需要相应签名和团队设备验证。

当前机器是 Mac，已具备 Node/npm，未发现 Windows 运行环境、dotnet、Wine 或 Windows 交叉编译器；仓库没有远程地址。不会自动上传代码或擅自创建远程构建服务。可在本机先实施可验证的编辑器、算法和媒体流程；Windows 特有部分的实机验收需 Windows 环境。

## 分阶段实施

1. 确认本设计，形成详细实现计划和模块接口；Windows 工程单独置于 windows/，不替换 Mac 产品。
2. 建立工程、核心时间线/镜头规则、保存读取与可操作的编辑器。
3. 接入真实来源录制、可选麦克风、区域选择与 Windows 鼠标事件。
4. 接通 MP4/GIF 导出与取消保护，以实际媒体测试验证。
5. 生成安装包，执行 Windows 设备验收，列明尚未完成的测试和签名状态。
